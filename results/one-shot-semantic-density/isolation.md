# Agent workspace isolation and frozen inputs

The three scored agents ran in separate `.work/one-shot-semantic-density/{rails,phoenix,loco}` workdirs. Each received a fresh Codex home. All three home configs had the same SHA-256 (`8539db0a9fb8772277ca187552aba3400fd9952695b138584b8d95fc4b2669f0`) and set `approval_policy = "never"`, `default_permissions = "workspace-only"`, `memories = false`, and `multi_agent = false`. The agents could write application files and install dependencies in their own workdirs. Rails used a workdir-local bundle, Phoenix used workdir-local Mix caches and a source alias for its container toolchain, and Loco used a workdir-local Cargo home and target directory.

An isolated preflight Codex agent created a file and installed/imported `is-number@7.0.0` in its own workspace. It received `Operation not permitted` when reading the parent prompt and a sibling prompt, and direct `docker info` was denied. Its workdir-local `harness/db.sh start` and `stop` both succeeded through the localhost check broker. An earlier probe also denied reading the parent repository and opening the host Docker socket. These probes preceded the final prompt freeze; the scored launches used the same permission configuration and broker mechanism. The final three home configs match byte-for-byte.

The broker bound to loopback, authenticated a distinct token per stack, pinned each token to that stack's workdir and development port, and accepted only named check/database actions; Phoenix toolchain calls bind-mounted only its own workdir. It did not give agents the host Docker socket. The copied spec, client, harness, prompt, environment, measurement rules, and scaffold were set read-only. Their SHA-256 contents were verified before and after each agent and again after independent gates. All three final workdirs still match the frozen fixture SHA-256 `3c80961922dadb5f7a41ce27e081e787a5d0cabfc3ae0094588aaeb79c5faa25`; the prompt SHA-256 is `7a992cd7f4a4e0be917bdefc93a6090d00c5ee2bb3483b06e58d114ea65a76e6`.

The browser/client preflight passed before the final workdirs were prepared. Two short preparatory Rails attempts used earlier prompt versions and were stopped, then all three scored workdirs and homes were prepared again from the final frozen fixture. Those attempts are excluded from scored effort and retained in the [failure ledger](failures.md). The [frozen manifest](frozen-fixture-manifest.json), [prompt](frozen-prompt.md), and [measurement rules](frozen-measurement.md) are copied into this result set.
