## Next design trial

The reference fixes correctness but does not establish that Vine, Lucid models, or Bouncer improve semantic density. The pinned APIs are available, yet the scored source still uses manual `Record<string, unknown>` extraction and an unchecked `store.rows<T>` assertion. Try typed request decoding and row decoding on one vertical slice, then compare complete code and behavior before expanding it. Vine numeric parsing must be strict, and protected writes must still check authentication, visibility, ownership, revision, then content fields. Lucid hydration must not replace page-first set queries or atomic writes with per-row work. Bouncer needs an adapter for this app's JWT viewer; add it only if the resulting authorization owner is clearer and smaller.

No runtime throughput benchmark was run for reference-1. Its gate and held-out results are diagnostic and do not alter the scored effort, size, or speed figures.
