# Results

- **`sizes.json`:** each stack's code size after every step (tokens, lines, and code lines), and what each step added or changed. Generated by `tools/report.py`.
- **`charts/`:** the charts, as SVG for the docs and PNG for sharing. Generated by `tools/report.py`.
- **`speed/<step>-<stack>.json`:** benchmarks of production images (`tools/bench/`). Each file holds every scenario's requests per second, p50, p95 and p99 latency, SQL statements per request and peak memory, plus the image size, cold start and idle memory.
  - `3-package-*` and `4-tune-*` are the step 3 and step 4 images.
  - `*-rerun-*` are the same images, benchmarked again later.
  - `6-polish-*` are the step 6 images.
  - `sensitivity/` holds Rails with two Puma workers, a setting no agent chose, and its same-session control.
  - `finished_at` records when each run ended. Runs from different sessions drifted on the shared machine, so compare within a session; see [the speed findings](../docs/findings/speed.md).
- **`security/<step>-<stack>.json`:** scans of production images (`tools/security/`): the 13 black-box checks, OSV-Scanner on the lockfile, and the stack's analyzer. `4-tune` is the baseline each agent hardened against, and `5-harden` and `6-polish` came after.
