# One-shot isolation preflight

Before any measured backend session, a disposable Codex agent ran with `workspace-only` permissions, `approval_policy = "never"`, memories disabled, and a fresh `CODEX_HOME`. The profile denied the filesystem root except the agent workdir and named read-only toolchains, while allowing network access for dependency installation. The [probe transcript](probe.md) records successful local file creation, npm package installation and import, denied reads of the parent repository and a sibling directory, and denied direct Docker access.

A second disposable probe ran inside the prepared Rails directory. Its [bridge transcript](bridge.md) records a denied read of the Phoenix workdir, denied `docker info`, and successful `harness/db.sh start 4101` and `stop 4101` through the coordinator. The host-side broker also passed the pinned live browser and WebSocket checks against the reference backend from the Loco workdir. The broker accepts only named check actions for the authenticated stack, verifies frozen hashes around each action, and does not pass a Docker socket into an agent or the Phoenix toolchain container.

All three workdirs were recreated from that manifest before the measured sessions. The original eight-step files and results were unchanged.
