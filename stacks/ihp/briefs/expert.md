# Guided IHP design brief

This is a **guided diagnostic** after three independent runs with the common prompt. The product contract and acceptance checks are identical. Use the pinned IHP 1.6 / GHC 9.10.3 / LiquidHaskell / Z3 environment. The target is an exemplary, maintainable backend for an imagined agent-maintained system above three million lines: a future agent should find a rule quickly, change it in one obvious place, and see an invariant fail at the earliest useful boundary. Favor domain meaning per line over a small line count by itself.

Treat the following as design constraints to validate against this exact IHP toolchain, not as uncompiled API sketches to paste. Use Hoogle and the pinned IHP source to confirm function names and types; compile a thin vertical slice early. Record where the framework does not support the desired form, and make the smallest explicit adaptation. In this isolated harness, `harness/ihp.sh start` launches the built server; it does **not** hot-reload source. Batch related edits, use Hoogle and focused checks for quick feedback, and run the release build at meaningful milestones. Stop the development server before the production gate, since both use port 4104.

## Rule ownership and types

- Put durable invariants in PostgreSQL where they protect every writer: foreign keys, uniqueness of an active share, valid status and revision, and the relationship between status and publication time. Keep `Application/Schema.sql` and fresh-database migrations consistent. The pinned schema compiler rejected inline `REFERENCES`, inline `CHECK`, `TIMESTAMPTZ`, and `STABLE`; use separate `ALTER TABLE ... ADD CONSTRAINT ... FOREIGN KEY/CHECK`, `TIMESTAMP WITH TIME ZONE`, and plain `LANGUAGE SQL` forms. A preparation probe confirmed that `CREATE TYPE article_status AS ENUM ('draft', 'published')` generates `Draft | Published` in Haskell. Avoid naming a custom enum `JobStatus`, which collides with IHP's job type.
- `new-migration` exists, but the dev shell defaults to a private PostgreSQL socket that is not running in this broker. Start `harness/db.sh start 4104`, then set `DATABASE_URL` **inside** the command, for example `harness/ihp.sh run sh -lc 'DATABASE_URL=postgres://agentmvc:agentmvc@host.docker.internal:54104/agentmvc new-migration "Create Conduit schema"'`. Review the output and run `migrate` against a fresh database. The probe's generated initial migration changed `SERIAL` IDs into plain `INT` columns without sequence defaults, so an insertion check is mandatory if you choose serial IDs. A generated migration is a starting point, not proof of equivalence with `Schema.sql`.
- Create a small pure Haskell policy core for product decisions that benefit from names and types: draft visibility, ownership, publication transition, revision expectations, pagination bounds, and room admission. Keep IO, request decoding, SQL, and IHP controller context at its edges. Introduce explicit `Viewer` and publication states where they reduce ambiguity; avoid mirroring every generated record in a second model just to satisfy an architecture diagram.
- Make the owner of each rule discoverable. A database constraint may deliberately enforce a rule also checked for a useful HTTP error; document that relationship. Do not scatter visibility, ownership, revision, or editing-key checks among route branches and SQL strings.
- Put LiquidHaskell on a small pure module that the running app actually calls. Prove at least one meaningful numeric invariant such as bounded room admission or revision monotonicity, and verify that an intentionally false refinement fails before removing the negative probe. State precisely what the proof covers. Prefer ordinary ADTs, exhaustive matches, and database constraints for properties they express more simply.

## IHP boundary

- Let IHP own the running HTTP application, controller context, persistence, migrations, WebSocket integration, and durable job worker. The pinned source exports `CanRoute`, `HasPath`, `get`, `post`, and WebSocket route helpers. `get` and `post` construct fixed front-controller routes; a custom `CanRoute.parseRoute'` uses parsers such as `string`, `parseText`, and `onlyAllowMethods`. Try a sum type with a constructor per API endpoint and a `Controller` action for each, confirming signatures in the local source. Make route coverage auditable with exhaustive matches on owned route types, and avoid stringly action dispatch. This IHP version's controller context is the WAI request and request vault; do not rely on unverified `putContext` / `fromContext` examples. If IHP's native route form materially fights this JSON contract, keep a compact, typed route layer and explain the concrete limitation.
- Use IHP generated records and query builders for ordinary single-record CRUD. Use typed, parameterized SQL for genuinely set-oriented reads, export snapshots, and the atomic compare-and-swap article revision update. A pinned compile probe rejected `COALESCE(${title}, column)` when `title :: Maybe Text`: the quasiquoter inferred `Text` and tried to coerce the `Maybe`. Use generated record updates or an explicitly supported typed SQL form for optional fields; do not spend a cycle on that sketch. If SQLSTATE 26000 recurs, a known narrow fallback keeps `TypedQuery`/`typedSql` inference but executes `tqSnippet` through `Hasql.DynamicStatements.Snippet.toStatement` and IHP's `sqlStatementHasql` with `tqResultDecoder`; verify the pinned signatures before adding it. Do not fetch a catalog into Haskell to filter and paginate, or do per-article author/favorite/tag lookups. List endpoints should push filters, visibility, ordering, counts, and pagination into bounded database work; inspect SQL statements per request.
- Decode inputs into endpoint-specific types or a small shared decoder. Centralize required/nonblank checks and the exact unknown-field behavior demanded by the security contract. Aeson can use `genericParseJSON defaultOptions { rejectUnknownFields = True }` for a chosen input type; default generic decoding does not imply that behavior. Keep shared-edit input narrower than owner-edit input. IHP 1.6 exports `requestBodyJSON`, `renderJsonWithStatusCode`, and `respondAndExit`; verify their behavior with the parsed request middleware and this API's status codes. Encode response and WebSocket event shapes in a small number of named functions or types rather than rebuilding ad hoc JSON in every branch.
- The pinned IHP source exports `hashPassword :: Text -> IO Text` and `verifyPassword` for an entity with `passwordHash`. Use them where the generated user model fits. Use a maintained JWT implementation available to this Nix project after checking the contract's signed-token expectations. Keep authentication, authorization, share-key hashing, and HTTP response headers at clear boundaries. Avoid handwritten cryptographic formats.
- Give each live room a clear concurrency owner. Admit editors atomically under the 100-editor cap, and send network messages outside the state transaction or lock. Persist content and revision in PostgreSQL; treat presence as per-instance ephemeral state. The current production contract runs one app instance, so state the multi-instance limit rather than adding an unverified distributed protocol.
- Start production only after PostgreSQL is ready; fail startup if migration fails. The image must start the IHP server and job worker from the three allowed environment variables. IHP documents optimized server and Docker outputs, but its default worker image is separate and this contract requires one image with migrations and worker; build a minimal correct image if practical and report its actual size. Test development and fresh production early enough to catch release-only errors.

## Working method and handoff

Implement a thin vertical slice, compile, then extend by cohesive domain capability. Run the full fixed development and production gates, formatter, linter, and the LiquidHaskell check. If a proposed API or abstraction raises code size or obscures behavior, change course and explain why. Do not tune only for the fixture or hide rules in excluded/generated files.

The pinned dev shell has HLint and `stylish-haskell`; Fourmolu was not present until an agent added it. The unmodified `nix flake check --impure` can resolve `devenv-root` to `/dev/null` inside the container; if that occurs, pass `--override-input devenv-root file+file:///work/app/.devenv/root` through `harness/ihp.sh run nix ...`. Include useful signatures and enable exhaustive-match warnings on owned route/domain modules if they compile cleanly with this scaffold.

Write a concise `AGENTS.md` map: each rule's owner, how to add a route/migration/job, the verified proof boundary, and any known scaling limit. In the final report, give check outcomes and notable failed attempts, source locations, framework features used, and cases where the pinned IHP APIs forced a different design. The reviewer will independently measure owned source tokens, SQL work, runtime behavior, and your effort.
