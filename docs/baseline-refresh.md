# Preparing a fresh baseline

Proposed next experiment: fresh builds across the project's selected stacks and build paths using `gpt-6.1-sol`. No new coding or runtime run is started by this document. The completed Clojure `gpt-6-sol`/`xhigh` cohort and all earlier inputs, source, failures and measurements remain historical evidence.

The current prompts have two concrete mismatches with the broker-owned checks. Fix these in a **new version of the inputs** before the proposed refreshed baseline. They affect agent effort and reported completion even when the application passes its independent gates.

| **Step 8 conflates the two entry points.** [Step 8, lines 15–22](../steps/8-live-editing.md#L15) says both commands run formatter/linter and security against production. The expert [one-shot prompt, line 15](../one-shot-v2-expert/PROMPT.md#L15) already distinguishes quick feedback, formatting, a complete development check and a fresh production check. Reuse that clarity for the sequential path. The generated [harness README, line 247](../tools/lane_run.py#L247) should state which commands start and stop services, which need a running server, which phase suites they include, and where their results appear. This is documentation of the existing lifecycle, not a request for more agent-managed infrastructure.
