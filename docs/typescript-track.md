# Why the TypeScript pilot uses AdonisJS

This pilot tests whether TypeScript can give agents Rails-like application ergonomics while keeping domain rules visible and checked. The selection is a hypothesis about the full Conduit contract, not a claim that AdonisJS will win on size or runtime.

AdonisJS 7 is the closest cohesive match to the contract. It supplies conventional routing and controllers, Vine validation, Lucid models and migrations, authorization policies, hashing, and a PostgreSQL-backed queue. Its [framework overview](https://docs.adonisjs.com/introduction) explicitly targets Rails-style backend structure; the [Lucid guide](https://docs.adonisjs.com/guides/database/lucid), [validation guide](https://docs.adonisjs.com/guides/basics/validation), [authorization guide](https://docs.adonisjs.com/guides/auth/authorization), and [queue guide](https://docs.adonisjs.com/guides/digging-deeper/queues) document the concrete features used in the scaffold. The queue package is experimental, so the fixture pins its exact version.

Two fixed protocol details require explicit extensions. The client expects JWTs, while AdonisJS's [built-in API guard uses opaque tokens](https://docs.adonisjs.com/guides/auth/access-tokens-guard). The editor requires raw bidirectional WebSockets, while AdonisJS's [first-party live channel is SSE](https://docs.adonisjs.com/guides/digging-deeper/server-sent-events). The scaffold preinstalls `jose` and `ws` and leaves the product-specific implementation to the measured agent. This cost belongs in the result.

[NestJS gateways](https://docs.nestjs.com/websockets/gateways) support `ws` directly, but its [first-party queue integration uses Redis](https://docs.nestjs.com/techniques/queues). Using that queue would violate this experiment's one-container-plus-PostgreSQL runtime contract; adding a PostgreSQL queue would be another integration. [Fastify's plugin architecture](https://fastify.dev/docs/latest/Reference/TypeScript/) is a strong option for a lean HTTP service, while its [database guide](https://fastify.dev/docs/v5.10.x/Guides/Database/) leaves persistence selection to the application. We infer that AdonisJS gives a better starting point for testing cohesive, low-noise application code under this contract. A later Fastify or Nest track would be a useful separate condition.

The TypeScript environment encourages inferred validator outputs, discriminated unions, exhaustive switches, `satisfies`, and small generics. Those features should remove repeated transport and encoding code while keeping each product rule in one named place. It explicitly discourages `any`, cast-heavy designs, boolean mode flags, and clever compression. Source tokens and lines will be measured, but the main v2 question is whether a fresh agent can safely find and change each rule.

The [TypeScript pilot environment](../one-shot-v2-typescript/ENVIRONMENT.md) and [frozen manifest](../one-shot-v2-typescript/fixture-manifest.json) are separate from the Servant condition. Both use the same [shared prompt](../one-shot-v2/PROMPT.md), measurement boundary, spec, client, and acceptance harness. Results must stay labeled by condition; neither pilot is an eight-step result.
