# Pitfalls

Each item is a problem that earlier AgentMVC runs hit or exposed, with what to do about it or what the tooling already does. Read the general sections before designing a condition, and your stack's section before writing its environment or brief.

## Harness and isolation

- An agent that can read the parent repository, a sibling workdir or the host Docker socket can see answers it should not. Before measured runs, prove with a disposable probe agent that those accesses and writes to frozen inputs fail while the workdir's `harness/db.sh start` and `stop` still work, and audit each transcript for reads of another stack's source.
- The runners were built on macOS with OrbStack. `tools/lane_run.py` denies the Docker socket at `/var/run/docker.sock` and at OrbStack's path under the current home, and the older IHP and Servant runners name the original host's home directory outright. On another Docker runtime, such as Docker Desktop or Colima, add its socket path to the deny rules and confirm with `tools/lane_run.py isolation SESSION.json` that the probe agent cannot connect.
- A reused Codex home, or one with memories on, can carry earlier sessions into a measured run. `tools/one_shot_agent.py` refuses a home that has sessions or lacks `approval_policy = "never"`, `memories = false` and `default_permissions = "workspace-only"`; give any new launcher the same checks and compare config hashes across stacks.
- Agents reach Docker only through a loopback broker that maps one token to each stack and accepts only named check and database actions, as `tools/one_shot_broker.py` does. Add a named action there instead of giving an agent the host Docker socket.
- A long-running command sent through a synchronous broker action holds the broker's global lock. The TypeScript pilot started `queue:work` that way, which queued every later request and left an orphaned container on the first independent production gate's port; bound ad hoc commands, clean up timed-out containers and expose a separate worker lifecycle, as the TypeScript expert broker does.
- Parallel lanes share one Docker resource lock, so at Go step 4 the broker waited past the launcher's ten-second bind deadline, and agent time includes such waits. `tools/lane_launch.py` waits for the lock before starting the clock, retries only that startup failure and publishes queue time separately.
- Any edit to the prompt, harness, broker, client, spec, scaffold or `stack.json` changes the hashed input: `tools/one_shot_agent.py` refuses a stale manifest, the lane and Clojure `freeze` commands refuse to replace a fixture, and the v2 `prepare` commands refuse to overwrite a workdir. Record the change as a new condition with its own hash and fresh workdirs, and keep any launch stopped for it out of scored effort.
- A harness defect found during a measured session cannot be fixed without invalidating that session's input. Before freezing, run the stack's preflight and drive every broker action the agent will use, including a migration and restart through the development bridge, a transactional enqueue, worker startup, a raw socket round trip and the compiled production image, with probes kept in a throwaway copy of the scaffold.
- Shared caches can defeat separate workdirs. Keep every cache per run: a workdir-local bundle for Rails, Mix and Hex caches for Phoenix, a Cargo home and target directory for Loco, a private Cabal store for Servant and a private Nix store for IHP.
- The workspace sandbox denies temp and cache paths outside the workdir, and `tools/one_shot_agent.py` passes the host `TMPDIR` through, so Bundler, RuboCop and the first Rust compile failed. Point `TMPDIR` and tool caches inside the workdir, or tell the agent to.
- The development server and the production gate share a port in each stack environment, and Phoenix and IHP agents hit that collision. Stop the development server before running the production gate.
- Host Chromium cannot launch inside the macOS sandbox, and Playwright writes `test-results` beside its tests, which fails on the read-only fixture mount. Run browser tests from a scratch copy in the pinned Playwright image, as `one-shot/harness/run-live-container.sh` and `one-shot/harness/Dockerfile.browser` already do.
- PostgreSQL's temporary init server accepts Unix-socket connections and then restarts, so a socket `pg_isready` can pass too early; this failed a Go step-3 gate and three TypeScript reference replays. `tools/lane_oneshot.py`, `tools/lane_review.py`, the Clojure runner and `tools/one_shot_live_bench.py` wait for TCP, but `tools/bench/bench.py` and `tools/one_shot_host/check-production.sh` still probe the socket, so wrap them as the lane runners do.
- A verbose reference session ID produced a 64-character database hostname, and DNS resolution failed before any timed sample. `tools/lane_evidence.py` now gives benchmark containers short hashed labels; keep container names short in any new runner.
- Rails answers a request that lacks `Accept: application/json` with 406, and that missing header broke the seeder, the load generator, the scanner, a smoke test and the demo. Send the header from every new script that calls an app.
- A spec or client bug that surfaces after launch fails every agent for the wrong reason. Validate each new feature with a throwaway implementation on separate ports before freezing, including a deliberately slow variant for polling tests; this caught a Retry-state bug in the live-editing client.
- The original editor in `frontend/src/` adopts every save response, so a late response can overwrite newer state. The one-shot client in `one-shot/frontend/` fixes this and has a browser test for it; build on that client.
- Leaks come from more than transcripts: a Python preflight log held disposable database and signing credentials, Clojure advisory scans quoted example passwords, and a shared Playwright cache exposed unrelated worktree paths. Scrub every published file with `tools/scrub.py`, check decoded JSON strings as `tools/lane_continue.py` does because escaped newlines beside Python decorators looked like email addresses, and test scrubber changes on a large sample.

## Prompts and command contracts

- Step 5 asks the agent to extend `bin/check-production` to run the security suite, but the host production gate already runs security and then destroys the app and database. The Clojure agent's extra run hit a stopped server and reported BLOCKED although independent checks passed; in a new fixture, delegate to the supplied gate and say that standalone security commands need a running server.
- Step 8 says both check commands run lint and security against production, so the Clojure agent chained development into production and added lint to production. Give each command one contract, and have the harness README that `tools/lane_run.py` generates say which commands start or stop services, which need a running server and which suites they run.
- Loose cleanup wording and nested gates inflate check counts: one step-8 agent counted 11 check invocations, which nesting turned into six development and seven production broker actions. Tell agents to use focused checks while editing and rerun only affected checks after cleanup, and report invocations and broker actions separately.
- Without an explicit rule, an agent may bypass the assigned framework: the first one-shot Loco agent wrote a standalone Axum and SQLx server inside the Loco scaffold. Say in the prompt that the framework must run the production app.
- A library in the scaffold or guidance is not a library the agent will use. Go's first step removed Huma, both AdonisJS builds skipped Vine and Lucid models, the Clojure builds used Malli for one schema at most, and the Python one-shot bypassed Ninja body decoding and Channels groups; name the boundaries you want and record what the final source actually uses.
- Under a fewest-tokens goal, agents dropped types at boundaries, such as untyped JSON in Loco and IHP, and hand-rolled token signing or password hashing. Ask explicitly for maintained crypto libraries and typed request decoding.
- Expert guidance is part of the condition, and its length varies by stack: 552 words of environment for Go, 666 for Rails and 1,170 for TypeScript. Give each guided prompt its own fixture hash and label, never pool it with unguided runs, and treat guidance amount as uncontrolled unless you cap it.
- The safe-evolution prompt used by Servant, the TypeScript pilot and the expert tracks is a different condition from the earlier semantic-density one-shots of Rails, Phoenix, Loco and IHP. Do not rank results across the two prompts.
- Expert advice can be wrong for the pinned version: preparing the IHP brief caught several sketches that did not compile or named functions that do not exist. Compile every sketch against the pinned toolchain before it goes into a prompt.
- The gates check behavior, not query bounds, rule ownership, proofs or direct tests, and the Clojure eight-step final tests only its health route. If one of those matters, ask for it in the prompt and measure it yourself.
- Agents leave documentation stale: the Go, Python, Rails and Clojure expert one-shots kept the scaffold's health-only README, and the Go eight-step `AGENTS.md` never mapped the export and live modules. Ask for the update if documentation matters, and count stale docs as part of the result.

## Correctness beyond the gates

- Every measured final app that got the supplemental reviewer probes failed at least one of them, though all had passed their frozen gates. Run the common, favorites and share probes in `tools/reviewer_common_http_probe.py`, `tools/lane_favorites_probe.py` and `tools/lane_share_probe.py` on each final app, and report them beside the gate verdict, not inside it.
- The probes are diagnostics the agents never saw. Validate each new probe against a conforming fake and a deliberately broken one, as the favorites and share probes were, label every finding as reproduced or source-inferred, and declare any promotion to a coding gate before launch.
- A probe cut short by an earlier failure is incomplete, not a score: Phoenix's common probe skipped a case after a long-title 500 and reported 16/20, and the Clojure one-shot's run timed out with no per-case summary. Report denominators and never turn an incomplete run into a zero.
- Revision edge cases slip past the gates. Rails and the Go one-shot mishandled `revision: null`, AdonisJS and Go shared edits answered stale `0` and `-1` with 422 instead of 409, and AdonisJS rejected one of two concurrent updates that omitted the revision; test omitted, null, non-integer and unequal integer values separately.
- Phoenix parsed the body before access checks and returned 422 where a stranger should get 403 and a missing article 404, and the Python and Clojure eight-step builds accepted `{"article":[]}` with 200 and bumped the revision. Check authentication, visibility, ownership and revision first, then reject any non-object envelope.
- A login throttle that checks its counter and increments it later lets a burst through: the Go one-shot, Phoenix, AdonisJS and the Clojure eight-step passed their frozen gates but let simultaneous bad logins exceed the cap. Reserve each attempt atomically before password work and give the window an expiry; the Go and Python one-shots had none, and Python's never reset even after a valid password.
- A capability checked before the row lock lets a revoked link keep writing: an AdonisJS keyed edit that waited behind a revocation still returned 200 and changed the article. Recheck the capability under the lock that rotation and revocation take; source review found the same gap in the Clojure one-shot.
- Live notifications get lost outside the edit path: source review found publishing without a revision broadcast in Rails and the Clojure one-shot, and deletion without closing admitted sockets in Phoenix and the Python and Clojure one-shots. List every write that changes a revision or access, and test the socket after each.
- Concurrency defects rarely appear under ordinary load. Force them with a barrier that holds the row until both writes block, as `tools/typescript_expert_heldout.py` does, and record the barrier with the result.
- Oversized input breaks handlers: huge numeric IDs returned 500 in Phoenix and the Clojure eight-step, and an accepted 255-character Phoenix title overflowed its slug column. Treat out-of-range IDs as missing, and check that every accepted length still fits storage after derived suffixes.
- The frozen share test checks only an extra inner field, so extra outer-envelope keys were accepted in both Go builds, the Python one-shot and the Clojure eight-step. Ask for exact envelopes if they matter; the share probe scores this as quality, not contract.
- Export snapshots read in separate statements under Read Committed can pair old article data with newer tags or counts, as source review found in Phoenix and the Clojure one-shot. Read the snapshot in one statement or under Repeatable Read.
- Rules stated in two places can disagree: Servant's registration accepted a seven-character password that password update rejects, and Servant and the TypeScript pilot also repeated draft visibility in list SQL. Give each rule one owner that every entrance calls, and probe each entrance.

## Measurement and comparison

- Agent reports and agent-run checks are not results. Rerun the development and production gates from the finished source, starting the app the way the agent's own entry points do, and take status from gate records, not the coding process's exit code.
- Size depends on who counts and how: the Rails expert agent reported 6,604 tokens against the reviewer's 6,010, and the unguided TypeScript pilot measures 9,355 or 9,407 depending on the classifier. Use the reviewer's `size.json`, and remeasure both sides with one classifier before comparing.
- `tools/measure.py` silently skips extensions missing from `stack.json`, which once dropped every Rails `.jbuilder` view, and excluding a directory by name once hid Phoenix's `lib/conduit/` code. Exclude by exact path, as `tools/one_shot_publish.py` does, and compare a finished workdir's file list with what was counted.
- Installer-generated queue schema inflates size: Rails copied about 2,000 tokens of Solid Queue schema into a migration, and GoodJob's unchanged migration adds 1,448 tokens to Rails whole-backend size. Set generated-code rules before launch and report owned and whole size side by side.
- Scaffolds differ: Loco's starter ships user authentication, the TypeScript scaffold is larger than Servant's, and the Go, Python and Clojure lanes start from maintainer-prepared scaffolds that already include packaging. Measure owned code against each untouched `.scaffold/`, and name the prepared-scaffold condition in any comparison.
- Formatters and languages lay code out differently: Loco averaged 6.7 tokens per line, Rails 8.1, Phoenix 8.8 and IHP 11 to 13, and the TypeScript pilot was about 29% smaller than Servant in tokens but had about 21% more lines. Compare size in tokens, and note that the line measurer can count Go block comments and Python docstrings as code.
- Uncached agent tokens swing with prompt caching: one comprehension run doubled its count while its total input rose only 5%. Report total input processed as well as uncached input plus output.
- Nonzero command counts include failed searches, unavailable host Git tools, infrastructure races and deliberate server stops, and failed brokered attempts mix code errors with environment errors. Do not read either as a defect count.
- Agent wall-clock time includes setup, compiles, Nix builds, broker queue waits and stalls, as in the TypeScript pilot's stall-affected 36 minutes, and eight-step totals add repeated onboarding and gates. Do not read time as implementation effort alone, or the gap between eight-step and one-shot totals as a speedup.
- Read a result as a tuple of stack, scaffold, guidance, build protocol, model, reasoning, CLI, prompt, fixture and output role. A shared prompt hash does not imply shared scaffolds, guidance or adapters, so publish `effective_fixture_sha256` beside the inherited `fixture_sha256`, as the lane one-shots do.
- Every measured run used `gpt-6-sol` at `xhigh`, so results include that model's familiarity with each stack. Changing model, prompt and harness together yields a new baseline; to isolate the model, run both models on one frozen fixture and record CLI drift, such as Codex CLI 0.159.0 for Clojure against 0.157.1 for earlier runs.
- `tools/lane_run.py` reads the model from the stack-wide `stack.json` at launch, and `results/cohorts.json` marks unknown identities as `null`, which never match each other. Record model, reasoning and CLI in each new cohort's launch config and run records, and regenerate and check the index with `tools/cohort_index.py` after adding runs.
- Deleting a failed attempt hides why a number was rerun. Keep failed setups and failed references, such as Python one-shot reference-1, fix the cause and rerun only the affected part; build repairs with `tools/lane_reference.py` and never credit their identity or effort to the measured parent.
- A crashed security analyzer can look like a clean scan with 0 findings, and an agent that only has the baseline scan cannot see findings its own fix adds, such as the Content-Security-Policy finding from Phoenix's secure-headers plug. Record analyzer errors as failures, rescan the final image, and judge each new finding against a JSON API.
- Code size reproduced within 4% across runs of one prompt, but effort and speed did not: three IHP runs from one prompt varied 1.65x in agent time and from about 1 to 372 article-list requests per second. Rank prompts on several runs each, and treat one-run gaps under about 20% as noise.
- The twelve comprehension questions score near the ceiling on apps this small and mostly test locating rules. Save and hash the answer key before launching a reader, as the evidence tools require, and use a cross-cutting change task to measure maintainability.

## Runtime benchmarks

- The benchmark host is a shared workstation, and identical images drifted by up to about 1.5x between sessions while unrelated work used 3 to 5 of its 18 CPUs. Compare only within one paired session, rerun the baseline image as a control when unchanged endpoints move, claim nothing under 1.5x, and record host load for every scenario.
- Agents that benchmark in parallel with each other get noisy numbers. Benchmark finished images yourself after all coding stops, one at a time, in at least two rounds in opposite order with fresh databases; `tools/lane_artifacts.py` refuses to export while any `logs/active.json` exists.
- Workloads are not interchangeable: step-4 tuning uses 1-second warmup and 3-second samples, final runs use 3 and 15 seconds over nine workloads, and the current-reference diagnostic used 2 and 10 seconds over two workloads. Never splice numbers across these conditions or across sessions.
- `foreign_container_cpu_percent_max` counts the unnamed k6 load generator, and the reused socket helper can also count the lane database. Read it as non-app container activity, not background load.
- Passing every gate does not bound SQL work: three IHP apps made 21, about 64 and about 2,081 statements per list request, and one Phoenix list made about 42 until an Ecto revision cut it to four and raised throughput from about 1.1k to 4.0k requests per second. Record SQL per request, which does not depend on timing, beside every throughput number.
- A fixed statement count can hide growing scan work: Phoenix's tag list used four statements, but with 10,001 articles its count and page plans each filtered 9,900 rows in sequential scans. Seed a larger catalog and run `EXPLAIN (ANALYZE, BUFFERS)` on the SQL the ORM actually emits, not a hand-written stand-in.
- The socket workload sends five saves per second, 20 per scenario in the lane rounds, and step-8 backend CPU stayed at or below 4.2% of one CPU, so it shows correct delivery, not capacity. The room cap is 100, so the 500-subscriber scenario spans five articles; keep that split in any new socket workload.
- The one-instance contract keeps presence, room caps and login throttles in process memory, so Rails runs one Puma worker and AdonisJS one Node process, while Phoenix's BEAM uses both CPUs inside one process. Throughput comparisons measure that topology, and more workers or replicas need shared admission and delivery first.
- Runtime success is not correctness: the nine workloads include no concurrent login burst, so the Clojure one-shot passed them all although it exhausted its heap in review. Show reviewer parity beside every runtime table; the lane runtime tools measure references only after full parity and with matching source and image hashes.
- Image size reflects packaging, not language: the semantic-density Phoenix image was 1,673 MB under `mix phx.server` and 165 MB as a release, and the Python one-shot's recursive ownership change adds a layer to a 373.7 MB image against 260.6 MB for the eight-step. Report packaging choices beside every image size.

## Rails

- The Rails images run one Puma process, which uses about one of the container's two CPUs, and no agent added workers, even when tuning. Two workers gave about 1.7x on most endpoints of the step-4 image and raised idle memory from 143 to 254 MB, but that was before live editing; now extra workers would split the in-process rooms and throttles.
- Rails 8 expects Solid Queue to have its own database, so using the app database means copying its installer schema into a migration. Classify that migration by comparing its body with the installed gem's template, as `tools/one_shot_publish.py` does; matching an earlier run's filename failed when the date prefix changed.
- On macOS, Solid Queue's forked worker crashed on fork safety during local checks. Keep any workaround scoped to local checks rather than production.
- Faye WebSocket writes must run on the EventMachine loop. The first Rails socket updates never reached subscribers until the agent scheduled its sends there.
- Rails agents install gems in a workdir-local `vendor/bundle`, and a reviewer gate that looked in `vendor/gems` failed before the app ran. `tools/one_shot_independent.py` now uses `vendor/bundle` when it exists.
- The Rails expert one-shot used `nil` for both an omitted and an explicit null revision, so `revision: null` changed the article instead of returning 422. Check whether the key is present before reading its value.
- The Roundhouse and Spinel compile probe found blockers for the exact Rails source and produced no throughput result. A compiled-Ruby speed claim needs product and deployment parity first.

## Phoenix

- The semantic-density Phoenix one-shot ran `mix phx.server` from the full Elixir image instead of a release. The expert scaffold now ships a release Dockerfile; ask for a release in any other Phoenix fixture.
- The original one-shot broker runs Phoenix's toolchain in `/work/app/conduit`, but that scaffold's `mix.exs` sits at `/work/app`, so agents added a root `conduit/` symlink alias. Align the two before reusing that broker, and exclude only that exact root path from size counts.
- Sobelow's JSON output needs Jason, which Sobelow's archive does not bundle, so Sobelow once failed silently and would have reported 0 findings. If you run Sobelow, put the project's compiled Jason on its path.
- Phoenix reads `force_ssl` at compile time, so enabling it to clear Sobelow's HTTPS finding broke the HTTP-based production gate. Terminate TLS at a proxy and document that, as the agent did.
- Phoenix Channels use their own message envelope, but the fixed editor speaks raw WebSocket frames. Route the upgrade through Bandit and WebSockAdapter; the expert scaffold predeclares that adapter.
- `Ecto.Changeset.cast/4` silently drops fields outside its permitted list, so it cannot enforce an exact envelope. Check the wire shape separately wherever the contract rejects unknown keys.
- The predicate `tag = ANY(tag_list)` cannot use the GIN array index, so the expert build's tag lists scanned the whole table. Use array containment, which the index supports.

## Loco

- Loco's default server-only mode does not run background jobs, so the export check stays pending. Start it with `--server-and-worker`, as the agents' entries and `tools/one_shot_independent.py` do.
- Loco's model and worker generators refuse to run once the migration marker and test module they expect are deleted as leftovers. Keep them if later changes may use the generators, or the agent has to wire files by hand.
- Rust and Loco have no mainstream equivalent of Brakeman or Sobelow. The environment's Clippy run with warnings denied is the closest static check.
- OSV reports RUSTSEC-2023-0071 in `rsa`, which arrives through `loco-rs` and `jsonwebtoken` and had no fixed release during the study. Check with `cargo tree` and the signing code whether the app uses RSA keys before counting it against the agent.

## IHP

- IHP's `unoptimized-prod-server` Nix target compiles at -O0 without IHP's production RTS flags, including `-N`, so the server runs on one core. The scaffold's `flake.nix` builds the image from that target, so IHP runtime numbers so far are a floor; use `optimized-prod-server` with an explicit capability count for speed comparisons.
- The IHP images so far were about 4.4 GB, which reflects their Nix packaging rather than a minimum for IHP, so do not compare that size across stacks yet. IHP's documented Docker output keeps the job worker in a separate image, while this contract needs migrations, worker and server in one.
- A shared Nix store held an earlier app's source where a later agent could read it, even with separate workdirs. Give each run its own Nix store volume cloned from a product-free prewarmed base, about 22.4 GiB each; building that base is not scripted yet.
- `harness/ihp.sh start` builds and starts the unoptimized production server, with no file watcher or hot reload. Tell agents to batch edits and build at milestones, and expect Nix build time inside agent time.
- LiquidHaskell only checks modules compiled with its plugin, and IHP run 1 set it up without proving any application rule. Name the invariant in a module the running app calls, keep its callers in checked modules, and test each proof with a deliberately false refinement, as the guided run did when its 0 to 100 room bound passed and a 0 to 99 bound failed.
- Rebuilding the IHP scaffold can undo four fixes: Z3 on the app-lib compiler PATH, an explicit Prelude import in proof modules, fixture directories hidden from the app-lib source scanner so it stops reading `.scaffold`, and a startup that runs `RunJobs` only when that binary exists. Keep all four.
- `IHP_MIGRATION_DIR` needs a trailing slash, and a development bridge without it stopped an agent run after 39 minutes before the app ever started. Preflight must apply a migration through the same bridge the agent uses.
- `new-migration` fails against the dev shell's default PostgreSQL socket, which is not running under the broker, so set `DATABASE_URL` inside the command. Review its output, since one probe's migration turned `SERIAL` IDs into plain `INT` without defaults, and test inserts after a fresh migration.
- The pinned IHP 1.6 schema parser rejects inline `REFERENCES`, inline `CHECK`, `TIMESTAMPTZ`, `STABLE` and `CREATE DOMAIN`. Use separate `ALTER TABLE ... ADD CONSTRAINT` statements, `TIMESTAMP WITH TIME ZONE` and plain `LANGUAGE SQL`; `CREATE TYPE ... AS ENUM` works, but not under the name `JobStatus`, which collides with IHP's job type.
- Two IHP sketches failed on the pinned version: `typedSql` rejected a `Maybe Text` inside `COALESCE`, and `putContext` and `fromContext` do not exist in IHP 1.6. Use generated record updates for optional fields, and read controller context from the WAI request and its vault.
- Typed SQL can fail with SQLSTATE 26000 from Hasql's stale prepared-statement cache, and IHP run 1 had to wrap those calls. Warn agents about it in an IHP brief, and review any such wrapper.
- `nix flake check --impure` can resolve `devenv-root` to `/dev/null` inside the container. If it does, pass `--override-input devenv-root file+file:///work/app/.devenv/root` through `harness/ihp.sh run`.

## Servant

- The Servant agent kept bodies and domain states as dynamic `Aeson.Value` and sent every dynamic SQL statement through one JSONB parameter, leaving the prewarmed `hasql-th` typed statements and `pg-migrate` unused. The route tree then checks handler coverage but not product rules; ask for typed records and statements if they matter.
- One `MVar`-protected Hasql connection serialized all database access in the Servant build. Check connection handling before reading its throughput as a framework result.
- The 7.15 GB Servant toolchain image is a prewarmed builder, and the delivered production image is 197.5 MB. Report only the production image.

## AdonisJS

- AdonisJS's API guard issues opaque tokens and its first-party live channel is SSE, but the client needs JWTs and raw WebSockets. The scaffold preinstalls `jose` and `ws`, and the integration code counts as the agent's measured source.
- The PostgreSQL queue package is experimental in AdonisJS 7, so the scaffold pins its exact version. Keep that pin, and avoid NestJS's first-party queue, which needs Redis and breaks the one-container-plus-PostgreSQL contract.
- The AdonisJS expert build trimmed padded titles, descriptions and bodies, silently changing stored text. Disable JSON trimming in `config/bodyparser.ts`, as the TypeScript reference does, and reject blank strings without trimming the rest.
- An invalid UTF-8 WebSocket frame killed the whole Node server in the expert build. Terminate the socket on its protocol error event, and probe with a malformed frame.
- Both AdonisJS builds left Vine validators and Lucid model classes unused, so their value under this contract is untested. Try them on one vertical slice first, with strict Vine numeric parsing, the same access-check order, page-first set queries, atomic writes and a Bouncer adapter for the JWT viewer.

## Go

- The prepared Go stack was Huma, chi, Bun and River, but step 1 removed Huma, the one-shot used it only for health and tags, and both builds decode most bodies by hand over `map[string]json.RawMessage`. Do not report a Huma or Bun result from these builds; a fully typed Huma and Bun reference is still open.
- The Go one-shot's single `rooms.mu` spans database work for unrelated articles, and Go list queries selected article bodies only to drop them. Use per-article room locks and body-free list projections such as Bun's `ExcludeColumn("body")`; neither effect on throughput has been measured.
- Go preflight caught a maintainer echo probe that closed TCP right after writing, which the host client saw as a protocol error, and a server shutdown-ordering bug. Use a normal WebSocket close handshake in probes, and prove that SIGTERM finishes in-flight requests before the pool closes.

## Python

- In Django, a filter placed before an annotation constrains the aggregate, so filtering `favorites__username` before `Count("favorites")` reported one favorite where two existed, and both Python originals failed 10 of 48 favorite cases. Filter membership with a subquery on the through table and keep the count annotation; `distinct=True` does not restore the lost rows.
- The eight-step Python edit route accepted `{"article":[]}` and bumped the revision. After locking and access checks, require a dictionary envelope and validate with `model_dump(exclude_unset=True)`, never apply arbitrary keys through a `setattr` loop, and avoid a route-level schema that would run before authorization.
- Signed-in comment rendering ran one follow lookup per comment in both Python originals, because `select_related("author")` does not batch the viewer's follow state. Annotate an `Exists` subquery for following, and check that the query count stays flat from 1 to 20 comments.
- The Python one-shot's presence counts raced: its first reference passed direct tests and the development gate, then failed the production browser test when two simultaneous joins did not settle at `2 here`. Serialize each client's ready, presence, update and revocation sends, read membership at send time, and refresh the joining client.
- Rooms live in one Uvicorn process, and development reloads only the web process, so job code changes need a worker restart. Multiple workers or replicas need shared admission, presence and delivery first.

## Clojure

- `buddy.hashers/verify` returns a map, and even an invalid result is truthy. Test `:valid`, and select `:argon2id` explicitly when deriving.
- Buddy's JWT `unsign` does not reject a token that has no expiry. Require the expiry and identity claims explicitly, and share one validator between HTTP and sockets.
- Reitit's Malli coercion strips extra keys by default and answers coercion failures with 400 and its own body. Set `:strip-extra-keys false` where the contract rejects unknown keys, map failures to the 422 envelope, and authenticate before coercion where auth errors take precedence.
- Passing the pool instead of the transaction's connection to `proletarian.job/enqueue!` creates a separate transaction. Pass the connection from `jdbc/with-transaction`, and prove commit and rollback in preflight.
- Proletarian's `start!` returns a boolean, a claimed job holds a pool connection while its handler runs, and the default is no retries. Return the worker itself from Integrant, stop workers before closing the pool, leave pool room for handler transactions, and configure bounded retries with idempotent handlers.
- The Clojure one-shot exhausted its JVM heap during concurrent bad logins because Argon2id work was unbounded across requests. Bound concurrent hashing, as the reference's two-permit semaphore does, and reserve login admission before password work without lowering hash cost.
- Atom update functions can retry, so side effects inside them can repeat, and the eight-step's one global live lock covered database reads and socket sends. Keep sends outside locks and swaps, and give each socket a bounded queue whose overflow reliably disconnects it; the one-shot tried to put its close marker into the same full queue.
- OSV-Scanner does not read `deps.edn`, direct pins are not a transitive lock, and clj-kondo is only a linter, not a security analyzer. Scan an export of the production basis `:libs` as a custom inventory, as `bin/dependency-scan` does; the first scan found Jetty and Bouncy Castle advisories that the scaffold now pins past.
- Final runs use 15-second samples, which do not establish a warmed JVM steady state, and AOT compiles Clojure to bytecode, not a native binary. Say so whenever JVM numbers sit beside native or BEAM results.
